kotoba note
システム仕様書

日本語・英語カードを登録し、タグで整理しながら双方向に復習するWebアプリケーション。

1. システム構成（正しい流れ）

ChatGPT認証はD1と直接接続しません。ブラウザからのリクエストをWorkerが受け、認証情報を確認してからD1へアクセスします。

  S[Cloudflare Sites

  A{ChatGPT認証情報
ユーザーIDを確認}
  D[(Cloudflare D1
カード・復習履歴)]
  R[結果をブラウザへ返す]
  U -->|画面操作・APIリクエスト| S
  S --> A
  A -->|認証OK| D
  A -->|未ログイン| X[ログイン要求]
  D -->|カード・履歴| R
  R --> U
要点：認証確認はWorker内で実行され、D1にはユーザーIDを条件にしてアクセスします。これにより、ユーザーごとのカードデータを分離します。

8. 推奨構成

  1. 現状維持：Sites + D1を使い、復習フローやUIの完成度を上げる。
  2. ファイルが増えた場合：CSV・音声ファイルをR2または外部ストレージへ分離する。
  3. Google中心にしたい場合：GAS + Sheets + Driveへ移行する。ただし、移行時はカードIDと復習履歴の引き継ぎを行う。
  4. 本格サービス化する場合：Python + PostgreSQL + OAuth + オブジェクトストレージへ段階的に移行する。

9. Sitesの特徴とCloudflareの役割

Sitesは、WebサイトやWebアプリを作成・公開するための開発基盤です。今回のkotoba noteでは、画面、API、データベースを一つの公開プロジェクトとして管理しています。

Sites上の役割今回のkotoba noteでの担当Cloudflareのサービス
Web画面の公開Mac・iPhoneに画面を配信Cloudflareの配信・実行基盤
サーバー処理カード取得、登録、編集、復習結果のAPICloudflare Workers
データベースカード・タグ・使用例・復習履歴の保存Cloudflare D1
ファイル保存将来的なCSV・音声ファイル保存Cloudflare R2等
認証連携ChatGPTのユーザー情報をWorkerで確認Sites / ChatGPT認証連携

Sitesを使うメリット

  • 画面、API、公開環境をまとめて構築しやすい。
  • Cloudflareの配信基盤により、個人利用でもスマホからアクセスしやすい。
  • D1を使えば、ブラウザの一時保存ではなくクラウドにデータを永続保存できる。
  • GitHubでソースコードを管理し、修正・ビルド・公開の流れを統一できる。
  • 今回のような個人用Webアプリを、サーバーを自分で運用せずに公開できる。

注意点

  • Sitesの認証方式や公開方式に依存するため、別環境へ移行するときは追加設計が必要。
  • D1は本格的な大規模DBというより、個人〜小規模アプリに適した構成。
  • Cloudflareの各サービスには容量・実行時間・料金プランなどの条件がある。
  • 外部サービスの障害や認証状態によって、データ取得・保存ができない場合がある。
まとめ：Sitesは「作る・保存する・公開する」を一体化しやすく、Cloudflare Workersが処理、D1がDB、配信基盤がWeb公開を担当します。個人利用のkotoba noteには、開発の速さと運用の軽さのバランスが良い構成です。

ローカルPythonのメリット

  • データを自分のMac内だけに置けるため、プライバシーを重視しやすい。
  • SQLite、CSV、音声ファイルをローカルで簡単に扱える。
  • FastAPIでAPIを明確に分離でき、将来Sitesやクラウドへ移行しやすい。
  • 外部サービスの認証・公開設定なしで開発を始められる。

注意点

  • Macがスリープ・電源オフだとiPhoneから利用できない。
  • Macの故障に備えてSQLiteとファイルを定期バックアップする必要がある。
  • 外出先から使う場合はVPN、トンネル、またはクラウド公開が必要。
  • ローカル利用でも、家族など他人が使う場合は認証を追加した方が安全。
個人利用での現実的な選択：MacBook中心で、iPhoneは同じWi-Fi内で使えればよいなら、FastAPI + SQLiteのローカル構成が最もシンプルです。Macが起動していなくても使いたい、外出先から使いたい場合はSitesやGASなどクラウド構成が適しています。
